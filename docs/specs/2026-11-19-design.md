# zavtracast-recs — дизайн

Дата: 2026-11-19

## Цель

Публичный сайт с постоянно обновляемой базой рекомендаций подкаста «Завтракаст».
Источник — транскрипты выпусков, а не шоуноты. Сайт обновляется сам после
выхода каждого нового выпуска, без участия человека.

Адрес: `https://fee1good.github.io/zavtracast-recs/`.

## Объём

- Старт: последние 10 основных выпусков (386–395).
- Дальше: каждый новый основной выпуск автоматически.
- Только основные выпуски: заголовок в RSS вида `Завтракаст <N> – ...`.
  Побочные шоу («Магнитное поле» и т.п.) пропускаются.
- Архив (выпуски < 386) вне объёма. Догоняется позже снижением
  `MIN_EPISODE`, без изменения кода.

## Что считается рекомендацией

Запись = личный опыт ведущего с произведением, высказанный в выпуске:
ведущий сам играл, смотрел или читал и дал оценку.

Не попадают: новости, слухи, анонсы, трейлеры, пересказ чужих обзоров.

У записи есть оценка `positive | mixed | negative`. По умолчанию сайт
показывает только `positive`, остальное доступно фильтром.

## Архитектура

Всё работает в GitHub Actions публичного репо `fee1good/zavtracast-recs`.
VPS и база данных не нужны.

```
workflow update.yml (cron раз в день + workflow_dispatch с номером выпуска)
│
├─ job discover   [Go]      RSS → список выпусков без data/episodes/<N>.json
│
├─ job transcribe [matrix: по выпуску на джобу, только для выпусков без транскрипта]
│    mp3 → ffmpeg (16 кГц, моно) → faster-whisper на CPU [Python]
│    → transcripts/<N>.json → push в приватный репо
│
├─ job classify   [Go]      транскрипт + шоуноты → Gemini Flash (structured output)
│    → валидация → data/episodes/<N>.json → commit в публичный репо
│
└─ job publish              data/*.json → site/data.json → deploy GitHub Pages
```

`concurrency` на уровне workflow: два запуска не идут одновременно.

### Хранилища

| Где | Что | Почему |
|---|---|---|
| `fee1good/zavtracast-recs` (публичный) | код, `data/episodes/<N>.json`, сайт | Pages на бесплатном плане требует публичный репо; Actions для публичных репо бесплатны |
| `fee1good/zavtracast-recs-transcripts` (приватный) | `transcripts/<N>.json` | полный транскрипт чужого контента не публикуем; нужен долго для переклассификации без повторной транскрипции |

### Секреты

- `GEMINI_API_KEY` — классификация.
- `TRANSCRIPTS_TOKEN` — fine-grained PAT: contents read/write только на
  `zavtracast-recs-transcripts`.

### Состояние выпуска

Выводится из файлов, отдельного state-файла нет:

1. нет транскрипта → нужна транскрипция;
2. транскрипт есть, `data/episodes/<N>.json` нет → нужна классификация;
3. `data/episodes/<N>.json` есть → готово.

Повторный запуск идемпотентен.

## Компоненты

```
cmd/recs/              CLI: discover | classify | build | eval
internal/feed/         разбор RSS → Episode (номер, заголовок, дата, mp3, длительность, шоуноты)
internal/record/       тип Record, валидация, генерация id
internal/classify/     промпт, JSON-схема, вызов Gemini, повторы
internal/site/         сборка site/data.json из data/episodes/*.json
transcribe/            transcribe.py + requirements.txt
site/                  index.html, app.js, style.css
data/episodes/         <N>.json — результат классификации
eval/golden/           <N>.json — эталонная разметка
.github/workflows/     update.yml, ci.yml
```

Go и Python не вызывают друг друга: их связывают шаги workflow и файлы.

### transcribe.py

Вход: путь к wav. Выход: JSON

```json
{"episode": 395, "model": "<whisper-model>", "duration": 8261.0,
 "segments": [{"start": 0.0, "end": 4.2, "text": "..."}]}
```

Модель и параметры (`compute_type`, `beam_size`) выбираются по результатам
спайка (см. «Риски»).

### classify

Вход в модель:
- транскрипт строками `[HH:MM:SS] текст`;
- шоуноты выпуска (HTML → текст) как подсказка для написания названий и
  определения говорящего. Источник истины — транскрипт.

Модель — актуальная Gemini Flash; точный id и лимиты бесплатного тарифа
сверяются по документации на этапе реализации. Весь транскрипт (~100–150k
токенов на 4 часа) отправляется одним вызовом, без нарезки.

Ответ — structured output по JSON-схеме. Ошибки API: 3 повтора с
экспоненциальной паузой, потом ошибка джобы.

## Формат данных

`data/episodes/<N>.json`:

```json
{
  "episode": 395,
  "title": "Завтракаст 395 – Nvidiot",
  "date": "2026-11-11",
  "page_url": "https://zavtracast.ru/395.html",
  "audio_url": "https://media.blubrry.com/zavtracast/...",
  "duration": 8261,
  "records": [
    {
      "id": "395-the-legend-of-zelda-ocarina-of-time-maxim",
      "title": "The Legend of Zelda: Ocarina of Time",
      "title_ru": null,
      "type": "game",
      "host": "maxim",
      "verdict": "positive",
      "summary": "Перепрошёл на эмуляторе, говорит, что игра почти не устарела",
      "t": 5412
    }
  ]
}
```

Поля записи:

- `type`: `game | movie | series | anime | cartoon | book | comic | other`.
- `host`: `dima | maxim | timur | guest:<имя> | unknown`. Определяется
  моделью по контексту (обращения по имени, шоуноты). Не уверена → `unknown`.
- `verdict`: `positive | mixed | negative`.
- `summary`: пересказ своими словами, 1–2 предложения, не цитата.
- `t`: секунда начала обсуждения.
- `id`: `<episode>-<slug(title)>-<host>`. Стабилен между прогонами, чтобы
  `git diff` показывал реальные изменения.

Одно произведение, два ведущих с разными оценками → две записи.

Сознательно не входит: год выпуска произведения, обогащение из внешних баз
(IGDB, TMDB), обложки. Можно добавить позже без смены формата.

### Валидация (Go)

Запись отбрасывается с логом, если:
- `type`, `host` или `verdict` вне допустимых значений;
- `t` < 0 или `t` > `duration`;
- пустой `title` или `summary`;
- дубль `id`.

Если отброшено больше трети записей выпуска — ошибка джобы, файл не пишется.

## Сайт

- Статика: `index.html` + `app.js` + `style.css`, без фреймворка и сборщика.
- `site/data.json` — все записи с полями выпуска, собирается командой `build`.
- Поиск по названию; фильтры: тип, ведущий, оценка (по умолчанию `positive`),
  выпуск. Сортировка по дате, новые сверху.
- У записи две ссылки: страница выпуска на zavtracast.ru и mp3 с таймкодом
  `audio_url#t=<t>`.
- Счётчик посетителей: GoatCounter (бесплатно для некоммерческих, без
  cookies). Аккаунт и код сайта заводит владелец репо.
- Деплой: `actions/deploy-pages` из job publish.

## Обработка ошибок

| Сбой | Поведение |
|---|---|
| RSS недоступен | падает весь запуск, следующий cron повторит |
| mp3 не скачался / транскрипция > лимита джобы | падает только джоба выпуска, выпуск остаётся в состоянии 1 |
| Gemini ошибка | 3 повтора, потом падение; на следующем запуске только классификация (состояние 2) |
| мусор от модели | порог валидации |
| параллельные запуски | `concurrency` |

Уведомления: стандартные письма GitHub об упавшем workflow.

## Тестирование

- Go юнит-тесты в `ci.yml` на каждый push: разбор сохранённой копии RSS,
  валидация, `id`, сборка `data.json`.
- `transcribe.py`: дымовой тест на 30-секундном фрагменте.
- Эталон: после первого прогона 10 выпусков владелец правит записи,
  результат сохраняется в `eval/golden/`. `recs eval` считает найдено /
  пропущено / лишнее по ключу (нормализованное название, ведущий). Не в CI:
  платный и недетерминированный вызов; запускается вручную при правке промпта.
- E2E: `workflow_dispatch` на одном выпуске → запись видна на живом сайте.

## Риски

- **Скорость faster-whisper на CPU-раннере** (4 vCPU, лимит джобы 6 ч).
  Выпуски идут 2–6 часов. Первая задача реализации — спайк: замер на одном
  ~4-часовом выпуске для нескольких моделей. Критерий: 4 часа аудио
  укладываются в ≤ 4.5 часа джобы. Если нет — нарезка аудио на части и
  matrix по частям с последующей склейкой сегментов.
- **Качество распознавания русской речи с англоязычными названиями.**
  Смягчается шоунотами в промпте; проверяется эталоном.
- **Лимиты бесплатного тарифа Gemini.** Один вызов в неделю укладывается с
  запасом; при бэкфилле архива — пауза между выпусками.
